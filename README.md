# qa-test-case-generator — 测试用例生成器

> 一键从需求生成结构化测试用例的**整合技能**：把需求评审、需求解构、场景树、边界分析、组合策略、状态转换、风险识别、功能类型启发式清单、接口/移动端/Agent/性能/安全专项、AI 输出评审与盲区补盲、防幻觉校验与覆盖率报告整合为一条**六步流水线**。

- **版本**：1.7.7
- **能力**：`Read Grep Glob WebFetch Bash`
- **分类**：Development / Testing
- **默认不读取代码实现**：用例验证"系统应该做什么"，而非"如何实现"

---

## 解决什么问题

把"帮我生成测试用例"这类模糊诉求，变成一条可追溯、可校验、有明确产出契约的流水线：

- 输入可以是**一句话需求 / PRD 文件（.md/.docx/.pdf/.txt）/ URL / 需求目录**，主文档含索引引用时自动读取全部子模块文档并合并
- 中间分析（评审、解构、风险、场景、边界、组合、状态）内联产出，不必每步单独落盘
- 最终交付**标准 9 列 XLSX** + 测试报告，含 P0-P3 分级、需求可追溯、覆盖率标注口径

## 何时激活

用户说"生成测试用例"、"帮我测试"、"设计测试"、"上传需求"、"开始测试"、"需求评审"、"边界分析"、"补盲"，或上传 PRD / 需求文档 / URL 时自动激活。也支持单独生成某模块用例，或评审已有用例。

## 硬约束（始终生效）

| 约束 | 说明 |
|------|------|
| **直接产出** | 必须在本次响应直接输出用例，不得只承诺"我将生成"；数据不足时先输出已有分析，再标注缺什么 |
| **覆盖诚实** | 必须写"基于现有需求文档的覆盖率"，禁止"全覆盖/100%"；缺失模块标"未覆盖+原因+建议补充"，**不得编造需求或用例** |
| **可追溯** | 每条用例带唯一 `TC_{模块缩写}_{功能缩写}_{序号}` 并关联 `REQ-xxx`；风险点带 `RISK-xxx` |
| **XLSX 交付** | 最终交付 `test-output/测试用例.xlsx`，另附 `test-output/测试报告.md` |

## 复杂度判定与深度

先判定复杂度，据此决定挖掘深度与用例规模。

| 维度 | 简单 | 中等 | 复杂 |
|------|------|------|------|
| 模块范围 | 单模块 | 2-5 模块 | 5+ 模块 / 跨系统 |
| 风险 | 低 | 中 | 高（资金/安全/核心链路） |
| 并发 | 无 | 少量 | 高并发 |
| 数据敏感 | 低 | 中 | 高（用户/财务） |
| 外部依赖 | 无/少 | 中 | 多/核心依赖 |

| 产出 | 简单 | 中等 | 复杂 |
|------|------|------|------|
| 需求总数（显性×倍数） | ×2 | ×3 | ×4 |
| 场景数（显性×倍数） | ×3 | ×5 | ×7 |
| 边界数（场景×倍数） | ×1.5 | ×2 | ×2.5 |
| **用例总数（显性×倍数）** | **×3** | **×5** | **×7** |

## 六步工作流

每步都要产出实际内容（内联分析即可），完成后过该步检查点。

### 第 1 步：输入解析与校验
- 识别输入：文字 / 文件（.md/.docx/.pdf/.txt）/ URL / 需求目录；主文档含索引引用时必须读取全部子模块文档并合并
- 三维校验：需求明确性（功能/目标/角色/成功标准）、上下文充分性（背景/约束/依赖/历史缺陷）、输入类型
- 评分 <4 或 4-6 时，列出缺失信息 + 具体追问；**先输出已有数据的部分分析**，再标注缺口

### 第 2 步：需求评审 + 三层解构
- **五维评审**（各 10 分）：完整性、清晰性、一致性、可测试性、可实现性；问题分 P0 阻塞 / P1 重要 / P2 建议，每条 P0/P1 必须带改进建议
- **三层需求**：显性（文档写明）、隐性（五问法：如果不？异常呢？假设呢？不存在呢？并发呢？）、衍生（换角色/场景/边界/关联功能/数据流向推导）
- **五维拆解**：输入、操作、状态、输出、规则
- **业务规则结构化**：`RULE-xxx：若[条件]，则[必须满足]`
- 产出需求解构表：`需求ID | 显性描述 | 隐性假设 | 风险点 | 疑问`
- 检查点：隐性需求 ≥3 条；五维齐全；每条需求可测试

### 第 3 步：分析建模（风险 + 场景 + 边界 + 组合 + 状态）
- **风险雷达（5 信号）**：变更类型、业务影响、技术复杂度、数据风险、集成风险；风险分 = 业务影响 × 概率 × 技术复杂度。每模块 ≥5 个风险点，高风险区域约 60% 测试资源
- **启发式清单**：按功能类型套用（表单/列表/购物车/支付/导入导出/审批/通知/权限），详见 [checklists.md](references/checklists.md)
- **场景树**：主路径 ×1、分支路径 ×2、异常路径 ×1.5、数据流 ×0.5；异常必须覆盖输入/状态/网络/依赖/并发/资源
- **四维边界**：输入、状态、时间、资源
- **组合策略**：参数 3-10 个 → Pairwise（≤全组合 10-30%）；>10 个 → 正交表（5-20%）；高风险 → 全组合
- **状态转换**：合法（状态数×2）、非法（×1.5）、临界（每条转换×1）、并发（高并发状态×2）
- **领域建模**（复杂项目）：状态转换图 / 数据流图 / 服务依赖图，必须输出可测的表而非只画图
- **批判思维**：至少挑战 3 个隐含假设
- 检查点：每个高风险点有概率+影响+缓解；边界覆盖 ≥3 个维度；非法状态转换已列

### 第 4 步：生成测试用例
- 套用设计方法（见下）与覆盖维度
- 每条用例只验证一个明确目标；预期结果客观可测、用"应/必须/会"；**测试步骤留空**由用户按实际系统补充（避免幻觉与返工）
- 按复杂度产出足够数量，P0-P3 分级并标注风险等级
- 检查点：主/分支/异常/边界齐全；字段级验证覆盖每个表单字段；预期结果可验证

### 第 5 步：AI 评审 + 盲区补盲
- **八维评审**（各 10 分，总分 ≥64/80 合格）：完整性、正确性、可执行性、风险覆盖、规范性、追溯性、一致性、冗余度
- **六盲区补盲**（每类 ≥2-3 条，共 12-18 条）：时序依赖、并发冲突、资源竞争、状态累积、数据一致性、第三方集成
- 问题用 `MISSING/WRONG/VAGUE/REDUNDANT/RISK/FORMAT` 标记并给出修正；系统性问题回退第 4 步重生成

### 第 6 步：防幻觉校验 + 输出
- **四维校验**：事实核查（查 `REQ/RISK/BD`）、一致性（需求↔用例、风险↔用例、场景↔边界）、可执行性（评分 ≥7）、来源追溯
- 六类幻觉处置：虚无功能→删除或标注；过度推断→降级为假设；数据编造→修正或标注 `[假设]`；时间/数值幻觉→对齐原文；跨模块矛盾→统一；依赖幻觉→标注前置假设
- 输出 `test-output/测试用例.xlsx` + `test-output/测试报告.md`（用例统计、覆盖率[标注口径]、缺口清单、高风险区域、回归分级）
- 回归分级：L1 冒烟 P0 <15min / L2 核心 P0+P1 <2h / L3 全量 P0-P3

## 设计方法速查

| 方法 | 适用 | 必用场景 |
|------|------|----------|
| 等价类划分 | 输入域 | 所有输入字段 |
| 边界值分析 | 边界 | 所有有边界限制字段 |
| 场景法 | 业务流程 | 核心业务流程 |
| 判定表驱动 | 多条件组合 | 多条件组合 |
| 错误推测 | 经验驱动 | 异常场景 |
| 因果图 | 复杂条件依赖 | 复杂条件组合 |
| 正交试验 | 多因素多水平 | 多因素兼容性 |
| 状态转换 | 状态机 | 有状态变化功能 |
| 风险驱动 | 高风险优先 | 高风险功能 |

## 覆盖维度（逐项自检）

- **功能**：主流程、分支、异常、边界、退出（退出/注销/超时）、状态转换
- **数据**：有效、无效、边界、特殊字符/超长、格式校验（邮箱/手机/身份证）、注入（SQL/XSS/命令）
- **字段级**（每个表单字段）：长度边界（1/最大/最大+1）、格式、注入、特殊字符、空值、默认值
- **权限**：角色权限、越权、数据隔离、功能权限、CSRF、路径遍历
- **集成**：模块间、接口、数据流转、异常处理
- **非功能**：性能、兼容性、可用性、安全、可靠性

## 输出契约

**测试用例.xlsx（固定 9 列，写入首个工作表）**

第 1 行表头（列顺序与名称固定）：

```text
用例编号,测试类型,功能模块,测试标题,用例级别,预置条件,测试步骤,预期结果,风险等级
TC_AUTH_LOGIN_001,功能测试,认证,正确凭据登录成功,P0,已注册用户u1密码符合规则,访问/login;输入用户名;输入密码;点击登录,跳转首页并显示用户名;Session建立,高
```

- 必须生成**真实 xlsx 二进制文件**（Bash 调用 Python，用 `openpyxl` 或 `pandas`+`openpyxl`），**禁止把 CSV 直接改名为 .xlsx**
- 每个字段写入独立单元格，字段内部的分隔（如步骤用 `;`）不拆列；表头必须存在；每条用例占一行
- 单元格按文本写入（避免编号、长数字被转成科学计数法或日期）；以 `=`、`+`、`-`、`@` 开头的内容必须保持纯文本，不得被识别为公式
- 表头加粗并冻结首行，列宽自适应；无需再考虑分隔符转义与 BOM
- 文件路径固定 `test-output/测试用例.xlsx`
- 编号规则：用例 `TC_{模块}_{功能}_{序号}`、需求 `REQ-模块-序号`、风险 `RISK-模块-类型-序号`、场景 `SC-...`、边界 `BD-...`
- 测试类型：功能/异常/边界/并发/安全/性能/兼容性/接口
- 用例级别：P0 关键（≤20%，核心流程 100%）、P1 重要（≤40%）、P2 一般（≤30%）、P3 可选（≤10%）；P0+P1 ≥60%
- 质量线：用例数 ≥ 需求点 ×3；每条平均预期结果 3-5 条；P0 用例 100% 覆盖现有需求

### 其他输出

| 产出 | 说明 |
|------|------|
| 覆盖率报告 | 必须标注口径，缺失写"未覆盖+原因+建议补充" |
